## Project overview

MedVision AI demonstrates an end-to-end computer-vision workflow: preparing a labelled image dataset, splitting records by patient, training a ResNet-18 classifier, evaluating it on a held-out test split, and exploring model activations in a Streamlit interface.

The repository contains an existing checkpoint and demo app. The data files are not included; users must obtain the NIH ChestX-ray14 dataset separately and comply with its terms.

## Task definition

The current model is a **binary classification experiment**, not a general chest X-ray interpretation system:

- **Positive:** records whose NIH `Finding Labels` field contains `Pneumonia`.
- **Negative:** records whose `Finding Labels` field is exactly `No Finding`.
- Records with other findings are excluded from this binary subset.

The label is derived from dataset metadata. It is not independent clinical ground truth.

## Features

- ResNet-18 transfer-learning pipeline using PyTorch.
- Patient-level train / validation / test split generation.
- Binary classification evaluation, including ROC-AUC, average precision, sensitivity, specificity, precision, F1, accuracy, and confusion matrix.
- Machine-readable evaluation report generated by `evaluate.py`.
- Streamlit interface with adjustable display threshold.
- Grad-CAM activation visualization, with explicit limitations.
- Synthetic-data unit tests that run without downloading the chest X-ray dataset.

## Quick start

Use Python 3.11 or 3.12.

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r requirements.txt -r requirements-dev.txt
```

Place the NIH ChestX-ray14 images and `Data_Entry_2017.csv` under `data/`, preserving the image filenames referenced by the CSV.

```bash
python prepare_data.py
python train.py
python evaluate.py
streamlit run app.py
```

`prepare_data.py` creates `data/train.csv`, `data/val.csv`, and `data/test.csv`. The split is performed by patient ID so that images belonging to the same patient do not cross dataset splits.

`evaluate.py` writes:

- `models/test_metrics.json` — metrics and evaluation metadata from the current test run.
- `models/roc_curve.png` — ROC curve from the same run.

The Streamlit dashboard reads these generated results. Before evaluation is run, the UI displays “Not generated” rather than presenting manually entered scores as current model performance.

## Tests

The unit tests create temporary images and CSV files; they do not require the NIH dataset.

```bash
python -m pytest -q
python -m compileall -q app.py dataset.py evaluate.py metrics.py prepare_data.py train.py
```

GitHub Actions runs the unit tests and Python syntax compilation on pushes to the main/feature branches and on pull requests targeting `main`.

## Model performance

Performance is specific to the checkpoint, test split, and threshold. Run `python evaluate.py` to generate the current metrics report. Do not compare numbers without also reporting the sample count, class distribution, threshold, and confusion matrix. Do not tune a threshold on the held-out test set.

No new performance claim is made by this repository update. See the [model card](docs/MODEL_CARD.md) for context and limitations.

## Safety, privacy, and limitations

- This is an educational research prototype, **not a medical device**.
- It must not be used for diagnosis, screening, triage, or treatment decisions.
- The model score is not a calibrated clinical probability.
- Grad-CAM is not a lesion outline and does not prove medically valid reasoning.
- Do not upload identifiable patient images or protected health information to a public demo.
- The app processes uploads in the Streamlit session and does not intentionally write uploaded images to application-managed storage.

Further evaluation would be required before making claims about generalisation, calibration, subgroups, external sites, or clinical utility.
